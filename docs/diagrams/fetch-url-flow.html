skill flow · fetch-url

Readable text, or the next tool takes over

Every fetch walks a priority chain: free local terminal browsers first, free reader APIs second, headless chrome last. Each stage either returns clean text or hands the URL to the next — and if all fail, you hear it.

Why this order

Local & free first

Terminal browsers render HTML to text in milliseconds — no network service, no quota, works offline on static pages.

Readers for the messy web

Reader APIs extract the article from Reddit, StackOverflow, GitHub, and docs pages that defeat terminal browsers.

Chrome as the last resort

JS-protected sites get a real headless browser. Costs startup time, so it only runs when the chain above fails — and failure is loud, never an empty page.
